INPUTDTO REFACTORING OPPORTUNITIES

This document outlines potential refactoring opportunities for InputDTOs across all domains
to reduce code duplication, improve maintainability, and create more consistent patterns.

- Occupant/AnomaliesInputDto (empty)
- Occupant/InterventionsInputDto (empty)

### B. Identical User Management InputDTOs
These are completely identical and should be merged:

- Operator/CreateGestionnaireInputDto (6 params: pkUser, email, lastname, firstname, phone, job)

### C. Identical Token InputDTOs

RECOMMENDATION: Merge into single Shared/TokenInputDto
